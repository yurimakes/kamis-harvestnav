# 로컬 인증키 관리

프로젝트 루트 `.env`의 `DATA_GO_KR_SERVICE_KEY`를 백엔드에서 읽습니다. 실제 `.env`는 Git에서 제외하고 예시 파일에는 실제 값을 넣지 않습니다. 브라우저·프론트엔드 변수로 전달하지 않습니다.

서버 프로세스에 같은 환경변수가 있으면 그 값을 우선합니다. 없다면 프로젝트 루트의 `.env`만 읽습니다. 다른 현재 디렉터리의 파일을 탐색하지 않습니다. 해당 인증 변수 한 개만 읽으며 셸 실행·변수 치환·다른 설정 자동 로딩을 하지 않습니다. UTF-8 BOM과 한 쌍의 따옴표를 지원하고, 중복 키·공백·미완성 따옴표·명백한 예시는 사용하지 않습니다.

## VS Code에서 한 번 설정

1. 저장소 최상위의 `.env.example`을 참고해 같은 위치에 `.env` 파일을 만듭니다. `frontend` 폴더 안이 아닙니다.
2. 다음 한 줄을 입력하고 `EXAMPLE_...` 부분만 포털의 일반 인증키 **Decoding 전체 값**으로 바꿉니다. 키를 채팅으로 보내지 않습니다.

```dotenv
DATA_GO_KR_SERVICE_KEY=EXAMPLE_REPLACE_WITH_DECODING_SERVICE_KEY
```

3. 파일을 UTF-8로 저장한 뒤 서버를 재시작합니다. `.env.example`은 변수명 안내일 뿐 실제 키를 넣는 파일이 아닙니다.

한 번 로컬 키를 저장한 뒤에는 프로젝트 루트에서 다음 명령으로 실행합니다. PS1 파일 실행이나 가상환경 활성화는 필요하지 않습니다.

```powershell
& '.\.venv\Scripts\python.exe' -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

기존 `-WithPortal` 옵션도 유효한 저장 키가 있으면 다시 묻지 않습니다. 환경변수/.env 값을 읽어 키의 존재 형식만 확인한 것으로, 실제 API 이용 승인·조회 성공을 보증하지 않습니다.

키를 변경할 때는 `.env`에서 해당 값을 수정하고 서버를 재시작한 뒤 같은 조회를 다시 실행합니다. 파일에 저장한 키도 비밀값이므로 공유 자료·Git·화면 캡처에 포함하지 않습니다. 이전 서버 프로세스 환경에 다른 키가 있으면 그 환경값이 우선하므로 서버를 종료하고 환경변수 없는 새 PowerShell에서 실행합니다.

테스트는 임시 `.env`와 합성 키로 격리해 실제 로컬 키를 읽지 않습니다. 단위 진단 보완이 함께 포함되어 중량 미확인 응답의 단위·단위크기를 확인할 수 있습니다. 키 저장과 실제 데이터 단위 확인은 별도의 단계입니다.

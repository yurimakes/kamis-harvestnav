# 공공데이터포털 연동

## 현재 연결한 API

현재 화면의 가격 조회는 `GET https://apis.data.go.kr/B552845/perRegion/price`를 사용합니다. 인증은 서버 환경변수 `DATA_GO_KR_SERVICE_KEY`를 우선하고, 없으면 프로젝트 루트 `.env`의 같은 변수를 읽습니다. Encoding 키는 한 번 URL 디코딩한 뒤 HTTP 클라이언트에 전달하며 Decoding 키를 권장합니다. 자체 KAMIS 인증 ID/KEY를 대신 사용하지 않습니다. 예전 자체 API 어댑터는 회귀 비교용으로 보존했고 앱의 기본 조회 경로는 포털 어댑터입니다.

요청: `returnType=JSON`, `numOfRows=1000`, `pageNo`, 조사기간 `cond[exmn_ymd::GTE]`/`cond[exmn_ymd::LTE]`(YYYYMMDD), 구분02·부류200·품목211, 품종·등급·시군구 EQ 필터입니다. 최대 5페이지/5,000건, 전체 25초 제한이며 일부 페이지만 받은 경우 정상 가격으로 표시하지 않습니다. 총건수 변경이나 페이지 누락은 다시 조회하도록 안내합니다. 정상 응답은 5분 캐시하며 조회 시각을 보존합니다.

지역은 서울1101·부산2100·대구2200·광주2401·대전2501을 지원합니다. 배추 품종은 봄01·여름(고랭지)02·가을03·월동06, 등급은 상품04·중품05입니다. 첨부 코드표 기준이며 계절별 실제 조사 여부는 응답으로 확인해야 합니다.

## 단위와 원천 근거

`exmn_dd_avg_prc`의 조사 평균가격을 `unit`과 `unit_sz`로 확인한 kg 중량으로 나눕니다. kg 단위와 양수 중량만 허용하며 단위 표기와 크기가 상충하면 중단합니다. 포기·상자·망 등의 무게를 추정하지 않습니다. `exmn_dd_cnvs_avg_prc`는 제공 명세에 환산평균가격으로 설명돼 있으나 변환 기준을 확정하지 않아 자동 kg값으로 사용하지 않습니다. 따라서 해당 필드가 있어도 원 조사 중량이 불명확하면 제외합니다.

각 관측에 원 조사가격·단위·단위크기·kg 중량·계산 방법을 보존합니다. CSV에도 함께 저장합니다. 화면은 지역 조사 평균이며 가락/구리 같은 개별 경매시장 가격을 의미하지 않습니다. 날짜·구분·품목·품종·등급·지역 코드가 요청과 다르면 분석하지 않습니다. 조사하지 않은 날짜를 보간하지 않으며 주간 비교의 실제 날짜와 간격을 표시합니다.

배추 응답의 `unit=kg(그물망 3포기)`, `unit_sz=10`은 포장 설명이 붙은 10kg 조사단위로 처리합니다. `10kg(그물망 3포기)`도 명시 중량과 단위크기가 일치할 때 허용합니다. 괄호 설명을 무조건 제거하지 않으며, 확인한 포장 표기만 인식합니다. 포기 수로 무게를 추정하거나 중량이 없는 포장 단위를 kg로 간주하지 않습니다.

## 제공받은 다른 명세의 역할

| API | 제공 구조와 적용 판단 |
|---|---|
| priceSequel/info | 조사일 기준 평균과 1~4주 전 비교가격. 지역/시장 필드가 없으므로 지역별 일별 자료로 합치지 않음 |
| recent/price | 최근 조사일 및 과거 비교 구간 가격. 실제 과거 조사일이 제공되지 않은 비교값을 임의 날짜의 관측값으로 만들지 않음 |
| katCode/* | 단위·크기·시장·법인·산지·포장·등급·상품 대중소분류 코드. 경매용 코드와 조사 가격의 211 코드를 직접 혼용하지 않음 |
| katRealTime2/trades2 | 정산일 필수, 낙찰일시·단량당 낙찰가·수량·단위물량. 거래시각 및 중량을 확인한 별도 집계가 필요 |
| katOrigin/trades | 시장과 정산일 필수인 정산 거래 원천. 현행 소문자 컬럼 사용, 과거 컬럼 대응표와 구분 |
| katSale/trades | 시장/정산일별 집계 거래 자료. 그룹이 다른 평균가를 단순 평균해 시장 전체가격으로 쓰지 않음 |
| katForecast/electronicInvoiceShipments | 외부 제공 예측물량·상하한·예측기간·단위. 앱이 학습한 예측이나 통계적 신뢰구간으로 표시하지 않음 |

같은 이름의 예측정보 (3)/(4)는 동일 파일이었습니다. 별도의 출하예약정보 명세를 받은 것으로 간주하지 않습니다. 모든 API를 무조건 호출하는 자동 수집 기능은 추가하지 않았습니다.

## 실행과 검증

기존 가상환경과 빌드가 준비된 Windows 프로젝트 루트에서:

```powershell
.\scripts\run-local.ps1 -WithPortal -SkipBuild
```

프로젝트 `.env`에 유효한 키를 한 번 저장한 뒤에는 `-WithPortal` 없이 `-SkipBuild`만 지정하면 됩니다. 기존 `-WithPortal` 옵션도 저장 키가 있으면 다시 묻지 않습니다. 이 옵션 자체는 키가 없을 때 프로세스용 입력을 받으며 파일에 저장하지 않습니다. 로컬 파일 저장과 읽기 규칙은 [로컬 인증키 관리](local-env.md)를 확인하세요. `.env.example`은 예시이고 실제 `.env`만 자동 읽습니다. 실제 키는 Git·브라우저·채팅에 넣지 않습니다.

실제 키로 조회하기 전까지 확인된 것은 명세 기반 구현과 합성 응답 시험입니다. 제공받은 명세에는 정상 resultCode의 값과 실제 JSON 중첩 예시가 없어 현재 `00`/`000`/`0`, 명세의 header/body 및 response 래퍼형을 검사합니다. 실제 포털 응답·단위·최소 3개 조사일 원천값 대조는 별도 수행해야 합니다. 조사값을 경매 단가나 미래 가격으로 치환하지 않습니다.

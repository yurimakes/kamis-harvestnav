# 실제 KAMIS 활용 검증 절차

> 현재 기본 조회는 공공데이터포털 `perRegion/price`입니다. 인증·단위·실행은 [현재 연동 가이드](portal-integration.md)를 우선 적용하세요. 아래 자체 API 설명은 이전 구현 기록이며 serviceKey와 혼용하지 않습니다.

이 문서는 제출 준비의 실행 순서입니다. 실제 가격 조회·현장 사용성·수익 효과의 완료 기록이 아닙니다.

## 1. 같은 조건으로 가격 조회

KAMIS 자체 API 인증으로 실행한 뒤 **KAMIS 가격 흐름**에서 2~4주의 기간, 도매 지역, 배추 품종·등급 코드를 확인합니다. 계절별 품종이 다를 수 있으므로 기본 코드가 현재 거래 품종이라는 가정을 하지 않습니다. 인증 오류와 자료 없음은 구별합니다.

## 2. 원천값 대조

같은 지역·품종·등급·조사일·kg 단위로 KAMIS 공식 화면의 최소 3개 조사일을 대조합니다. 공식 화면이 포기·상자 단위이면 임의 중량으로 바꾸지 않습니다. 단위·품종이 다른 자료는 비교에서 제외합니다. 자동 API 검사 통과와 이 대조 작업을 별개로 기록합니다.

기록 항목: 검증 시각, 조회 시작/종료일, 품목·품종·등급·지역 코드, 조사시장, 실제 단위, 조사일별 공식값과 앱값, 일치 여부, 검증자 구분(개발자/실제 사용자). 인증 원문·개인정보는 넣지 않습니다.

## 3. 근거 저장

**조회·분석 근거 JSON 저장**으로 출처·조회 시각·요청 코드·선택 관측값·분석값을 보존하고, **선택 가격표 CSV 저장**으로 숫자를 대조합니다. 결측/중복은 전체 요청 기준이며 관측 건수는 선택 시계열 기준입니다. 7일 이전 최근 관측값을 비교하므로 실제 간격이 8일 이상일 수 있습니다. 비조사일 보간은 하지 않습니다.

## 4. 판단 지원 흐름 확인

조회 자료에서 변화율과 비교일을 확인한 뒤 **이 자료를 참고해 가격 −10% 조건 비교**를 누릅니다. 장표에서 기본·스트레스 수취액을 비교하고 **조건·결과 저장**으로 참고 자료와 사용한 가정을 함께 보존합니다. −10%는 예측값이 아닌 검토용 가정이며 원래 경매 단가를 바꾸지 않습니다. 추가로 바꾼 하락률은 저장 자료에 구분됩니다.

## 5. 내부 사용성 확인

실제 참여자가 있을 때만 수행하고 기록합니다. 과제는 ① 출하량 수정 ② 차량이 추가되는 조건 확인 ③ 최대 수취액 배분 적용 ④ KAMIS 조사값과 경매 가정값 구분 ⑤ 조회 자료 저장입니다. 완료 여부, 막힌 지점, 오해한 용어, 개선점을 기록합니다. 개발자가 직접 확인한 결과는 내부 조작 확인이며 농업인 현장 시험으로 부르지 않습니다. 수행 전 시간 절감률이나 만족도를 작성하지 않습니다.

## 6. 보고서 반영

보고서는 이용 배경 → 실제 KAMIS 조회 조건과 활용 과정 → 확인한 결과 → 한계와 확산 계획 순으로 작성합니다. 합성 수취액 비교를 실제 농가의 매출·순이익 증가로 쓰지 않습니다. 현재 연결하지 않은 AI 모델, 이전 별도 실험의 MAE 개선율을 이번 KAMIS 성과로 쓰지 않습니다.

현재 필수 미완료: 실제 인증 조회, 현행 기간별 명세·코드표 대조, 원천값 대조, 실제 이용 기록, 공식 제출 양식 최종 확인. 제출 전 개인정보·인증정보를 제외한 증빙만 선택합니다.

관측 변화율이 음수이면 **관측 하락률을 같은 하락 가정으로 비교**하는 추가 버튼을 제공합니다. 조사 가격의 실제 과거 하락률을 경매가에도 동일하게 가정하는 스트레스이며, 두 가격 사이의 전이 관계나 미래 경매 하락률을 검증한 값은 아닙니다. 저장 자료의 `assumption.basis`는 이 경우 `observed_change_scenario`, 별도 −10% 검토는 `manual_review`로 구분합니다.
